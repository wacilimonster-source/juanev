# 工地隐患检测接口文档（v1\.0）

## 1\. 接口概述

本服务提供基于多模态大模型的图像智能分析接口。客户端需通过 `multipart/form-data` 格式上传摄像头采集的图片文件，并指定任务类型（taskType）。系统将对整张图片进行视觉分析，自动识别画面内隐患目标，最终输出隐患框坐标与中文标签。

🆕 特性：支持在请求参数中动态指定模型推理地址（modelUrl）和模型名称（modelName），系统将优先使用传入的参数；若未传入，则自动降级使用服务端配置的默认值。

- **请求方法**：POST

- **Content\-Type**：multipart/form\-data

- **认证方式**：与主接口一致（如 Bearer Token / API Key）

## 2\. 全局说明

### 2\.1 taskType 场景定义

|taskType|场景名称|描述|
|---|---|---|
|1808|裸土未覆盖|识别画面中成片明显未覆盖的裸土；小块零星裸土、被网半遮的土面不识别|
|1809|防尘网破损|识别防尘网破损、撕裂、破洞、翻卷脱开、整段缺失；网面褶皱、搭接缝、阴影造成的疑似透空不识别|
|1810|出渣车封闭|识别渣土运输车车厢顶部密闭状态；仅判断车厢顶部遮盖情况，不判断超高、超载、清洗状态，看不到车厢顶部则无输出|
|1811|出渣车道路遗撒|识别路面渣土撒漏、条带状痕迹、点状渣土土块、成片泥饼；夜间、暴雨积水路面、本身是土路不判定|
|1812|围挡破损|识别围挡立面破洞、板块缺失、板面撕裂翻起、凹陷外鼓；广告、喷绘、涂鸦、浮尘不算破损|
|1813|围挡缺失/不连续（含大门敞开）|识别围挡整段缺失、可通行缺口、围挡中断未搭接；大门敞开属于围挡缺失极端场景纳入该任务，单帧仅判断画面内连续性，大门有车、有人进出/消防规划开口不判定缺失|
|1814|物料堆放杂乱|识别物料越界、超高、混堆、占用通道、散料未归堆；无标线参照物画面无输出|
|1815|渗漏水|识别混凝土结构湿渍、流挂水痕、析白返碱、霉斑、明水；暗光逆光、水面强反光降低置信度|
|1816|蜂窝麻面|识别混凝土蜂窝、麻面缺陷；远距离、强侧光、抹灰面不适用，最多输出 3 处缺陷|

> 说明；大门敞开合并至围挡缺失/不连续场景，大门敞开作为该场景的极端案例。
> 
> 

### 2\.2 label 标签清单（中文）

|taskType|场景名称|label 可选值|
|---|---|---|
|1808|裸土未覆盖|有裸土未覆盖、无裸土未覆盖|
|1809|防尘网破损|有防尘网破损、无防尘网破损|
|1810|出渣车封闭|车厢已封闭、车厢未封闭|
|1811|出渣车道路遗撒|有出渣车道路遗撒、无出渣车道路遗撒|
|1812|围挡破损|有围挡破损、无围挡破损|
|1813|围挡缺失/大门敞开|围挡缺失/大门敞开、围挡正常连续|
|1814|物料堆放杂乱|物料堆放杂乱、无物料堆放整洁|
|1815|渗漏水|有渗漏水、无渗漏水|
|1816|蜂窝麻面|有蜂窝麻面、无蜂窝麻麻面|

### 2\.3 modelResult 返回规则

⚠️ 重要约束：`modelResult` 为 JSON Array 类型，非字符串。若识别失败或无目标，数组字段返回空数组 `[]`，不返回 null。

统一返回格式（所有 taskType 复用这套结构）：

```json
[
  {"bbox_2d": [92, 83, 799, 139], "label": "xxx"},
  {"bbox_2d": [108, 512, 349, 556], "label": "xxx"}
]
```

|字段|类型|描述|
|---|---|---|
|bbox\_2d|Array\[Integer\]|\[左上x, 左上y, 右下x, 右下y\]，原图绝对像素坐标|
|label|String|隐患中文标签，参考上方 label 清单|

## 3\. 接口参数

### 3\.1 请求入参（form\-data）

|参数名|类型|是否必填|说明|
|---|---|---|---|
|imageFile|File|是|图片文件|
|taskType|String|是|任务编号，1808\~1816|
|modelUrl|String|否|模型推理地址，不传使用服务端默认配置|
|modelName|String|否|模型名称，不传使用服务端默认配置|

### 3\.2 响应参数

|字段|类型|描述|
|---|---|---|
|code|Integer|状态码，成功为 200，校验失败为 400|
|message|String|提示信息|
|data|Object|业务数据对象|
|data\.taskType|Integer|传入的任务类型|
|data\.fileName|String|上传的图片文件名|
|data\.modelResult|Array|分析结果（详见 2\.3 节）|
|data\.modelUsed|String|🆕 本次实际使用的模型名称|
|data\.baseUrlUsed|String|🆕 本次实际使用的模型服务地址|

## 4\. 完整调用示例

### 4\.1 场景一：裸土未覆盖（taskType: 1808）

请求示例（cURL）\- 使用服务端默认模型：

```bash
curl.exe -X POST "http://localhost:8000/api/v1/image/analysis" `
  --form "imageFile=@C:\Users\Administrator\Desktop\工地隐患-标注\test01.jpeg" `
  --form "taskType=1808"
```

请求示例（cURL）\- 🆕 动态指定外部模型地址和名称：

```bash
curl.exe -X POST "http://localhost:8000/api/v1/image/analysis" \
  --form "imageFile=@C:\path\to\test01.jpeg" \
  --form "taskType=1808" \
  --form "modelUrl=http://172.35.1.1:8080/apis/ais-v2/chat/completions" \
  --form "modelName=ev-vlm-35b"
```

响应示例（JSON）：

```json
{"code":200,"message":"success","data":{"taskType":1808,"fileName":"test01.jpeg","modelUsed":"qwen3.5-vl-35b","baseUrlUsed":"http://172.35.1.1:8080/apis/ais-v2/chat/completions","modelResult":[{"bbox_2d":[93,357,138,451],"label":"有裸土未覆盖"}]}}
```

## 5\. 补充说明

1. 无隐患识别结果时，`modelResult` 返回空数组 `[]`。

2. bbox\_2d 为原图像素绝对坐标，顺序：左上x、左上y、右下x、右下y。

3. modelUrl、modelName 为可选参数，传入后优先使用；不传读取服务端默认配置。

4. 每个场景最多返回 3 处缺陷框。
