3.3 下发与回传报文定义改

两套平台（绿化平台 / 隐患平台）的上下行接口字段完全一致，仅接口地址区分：绿化下发为 POST /api/model/xingji/open/patrol/inspection/record、回调为绿化平台地址；隐患下发为 POST /api/model/xingji/open/hazard/patrol/inspection/record新、回调为隐患平台地址（{隐患平台地址}/analyse/public/smartPatrol/analysis/receive）。

接口② 下发巡视记录（工地平台 → 极星，POST，application/json）。

字段（dataList 元素内）类型必填说明
taskIdString是任务 ID；同一次下发的拆分记录共用
positionCodeString是点位编码
inspectionRecordIdString是工地平台巡视记录 ID；同批拆分记录共用，回传时原样带回
imageUrlString是巡视记录图片地址；同批拆分记录共用
taskTypeArray[Integer]是场景 ID 数组（如 [1803,1804,1806]）；单场景也传单元素数组（如 [1803]），口径统一
 
POST /api/model/xingji/open/patrol/inspection/record
Content-Type: application/json

{
  "dataList": [ {
    "taskId": "e9ac5bdfdcfe4e7d8f72b39251011276",

    "inspectionRecordId": "R-20261012-089",

下发校验：taskType 为空数组、缺字段或含不支持的场景 ID 时，整条返回失败（code 1），不入库、不拆分，由工地平台修正后重新下发。

5. 点位配置规则

应用差异说明新：「工地隐患监测」应用取消「点位配置」页面，无需上传标注 JSON 与配置参考图；「点位管理」仅作只读列表展示（点位编码、点位名称、接入状态、创建时间），由工地隐患平台下发自动创建后即可直接参与分析。以下 5.1 及点位配置细则仅适用于「无人机巡检识别（绿化）」。
配置项规则
点位来源全部由工地平台下发自动创建，极星侧不提供手动新增与删除。
参考图每点位 1 张。未上传时使用系统默认图；支持上传本地图片替换，并可一键恢复默认图。参考图仅作底图与标注预览，不参与模型入参。
标注 JSON每个点位上传 1 个 COCO 单图标注文件（含 images / annotations / categories 三个顶层字段）。上传后解析并在参考图上叠加显示标注区域，供人工核对；分析时该文件作为 jsonFile 原样传给接口。
配置状态已上传合法标注 JSON 记为「已配置」，否则「未配置」；未配置的点位不参与分析。
场景与配置关系改点位不绑定场景，1803 / 1804 / 1805 / 1806 / 1807 共用同一套参考图与标注 JSON，记录携带哪个 taskType 就调用对应场景。
配置生效上传标注 JSON 后即时生效（页面无「保存配置」步骤）；对后续新到的巡视记录生效，已完成的历史记录不回溯重算。
标注 JSON 字段说明：categories 定义类别——1 硬化路面、2 绿化、3 建筑。

5.1 标注 JSON 解析与渲染

环节规则
解析取 images[0] 的 width / height / file_name；遍历 annotations，读取 category_id（映射类别名）、segmentation[0]（扁平坐标 [x1,y1,x2,y2,…]，可为浮点）与 area（像素²）；iscrowd=1 的条目跳过。
渲染以参考图为底图，按 segmentation 坐标叠加多边形，并按类别配色（1 硬化路面 / 2 绿化 / 3 建筑）；叠加仅作人工核对，不参与编辑与模型入参。
清单与摘要右侧「标注清单」逐条列出 类别 / 面积（px²）/ 占全图比例（area ÷ width × height）；「JSON 摘要」显示 标注文件 / 图像尺寸 / 标注条数。
校验缺 images / annotations / categories，或缺 width / height，上传即拦截提示（点位保持「未配置」）。

说明：占比取多边形 area，不等于 bbox 外接矩形面积；坐标为浮点，渲染按原值绘制。

6. 分析流程与自动回传

收到巡视记录（可含多场景）改→ 按场景拆分新→ 匹配点位→ 校验点位已配置→ 下载图片→ 读取标注 JSON→ 调用模型→ 组装识别结果→ 自动回调工地平台

分析完成后自动回传，无人工复核环节；拆分后每条记录调用模型一次（注：「工地隐患监测」无「校验点位已配置」与「读取标注 JSON」步骤，下载图片后直接调用 /api/v1/image/analysis新）。多场景拆分口径：下发报文中同一条巡视记录可携带多个场景 ID（taskType 数组）；极星收到后按场景拆分为多条单场景记录，拆分后每条记录独立分析、独立回传；同批记录共用 taskId / inspectionRecordId / 点位与图片，工地平台按 inspectionRecordId + taskType 关联；同批共用同一图片（绿化同时复用标注 JSON），平台只下载 / 读取一次，各拆分记录复用；每条分析完成即独立回传，不等同批全部完成。改

回传口径：工地平台接收的 modelResult 即模型返回内容原样（1803 / 1808~1816 为目标框数组、1804 为绿化占比、1805 为硬化路面占比、1806 / 1807 为状态判定结果）；极星不做二次加工。改

7. 记录保留与自动清理

巡视记录（含原图、识别结果与回传报文）仅保留固定时长，超出部分自动清理，避免存储无限增长；保存时长支持配置。

7.1 保留策略配置

配置项规则
保存时长必填。默认 30 天，仅支持自定义 1～3650 天整数（不提供快捷选项），超范围禁止保存并提示。
自动清理开关，默认开启；关闭后超出时长的记录不再清理，页面给出风险提示。
每日清理时间HH:mm，默认 03:00，建议业务低峰时段。
配置生效保存后立即生效，对后续清理任务生效。
恢复默认一键恢复为「30 天 / 自动清理开启 / 03:00」。

7.2 清理规则

数据起始时间
保留期起点 = 当前日期 − 保存时长 + 1 天（如 2026-10-12 保留 30 天 → 起点 2026-09-13 00:00）
早于保留期起点的记录（含原图、识别结果、回传报文）在每日清理时间删除，不可恢复

自动清理开启时每日执行一次，关闭时不执行；点位配置与点位基础信息不参与清理，长期保留；缩短保存时长后，超出新时长的记录在下次清理时一并清理。

7.3 页面内容

区块内容
保留策略保存时长（自定义 1～3650 天）、自动清理开关、每日清理时间、恢复默认 / 保存设置；关闭自动清理时展示风险提示。
存储概览记录总数、占用空间。
清理记录最近 5 次清理日志：清理时间、清理条数、释放空间。

保留策略仅在「记录保留设置」页维护，巡视记录列表页不展示保留策略提示。
